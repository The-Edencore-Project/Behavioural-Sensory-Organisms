# 🫀 MODE 3 — Concept Paper  
## E‑CORE Runtime Loop  
### “The Nervous System of the Edencore Organism”

---

# 1. Introduction  
The E‑CORE Runtime Loop is the **central physiological cycle** of the Edencore organism.  
It is not a scheduler, not an automation engine, and not a ruleset.  
It is the **heartbeat** that continuously:

- senses  
- evaluates  
- predicts  
- coordinates  
- stabilises  

The loop runs at a fixed interval (the “tick”), and every tick represents one full cycle of organismal awareness.

This paper defines the conceptual architecture of that loop.

---

# 2. The Purpose of the Runtime Loop  
The Runtime Loop exists to prevent the house from behaving like a collection of independent devices.  
Without it, each subsystem would act on its own timing, creating:

- noise spikes  
- pressure shocks  
- light flicker  
- vibration stacking  
- conflicting actions  
- occupant discomfort  

The loop ensures the house behaves as **one coordinated organism**, not eight competing machines.

---

# 3. The Four Phases of the Loop  
Every tick of the Runtime Loop passes through four strict phases.  
These phases are non‑negotiable — they are the physiology of the system.

---

## 3.1 Phase 1 — **Perception** 🧩  
The loop gathers raw input from:

- **ENVO** (temperature, humidity, CO₂, sound, vibration, pressure)  
- **SAC** (movement, entry, perimeter events)  
- **NEMO** (external signals, weather shifts, neighbourhood timing)  
- **APLO** (mechanical cycle states)  
- **HVAC** (load, pressure, airflow)  
- **LUMA** (ambient light levels)  
- **MEDI** (soundscape)  
- **MOTA** (mobility requests)  

This phase answers:  
**“What is happening right now?”**

---

## 3.2 Phase 2 — **Interpretation** 🧠  
The loop converts raw perception into meaningful internal state:

- comfort deltas  
- predicted discomfort  
- subsystem readiness  
- conflict likelihood  
- noise/vibration risk  
- pressure stability  
- occupant posture (active, resting, absent)  
- environmental drift  

This phase answers:  
**“What does this mean for the organism?”**

---

## 3.3 Phase 3 — **Coordination** 🔗  
This is the decision‑making phase.  
The loop determines:

- which subsystems need to act  
- which must wait  
- which must soften  
- which must dominate  
- which must suppress their behaviour  

The **dominance engine** resolves conflicts using the E‑CORE priority hierarchy:

1. Safety (SAC, ENVO)  
2. Environmental stability (HVAC)  
3. Mobility & accessibility (MOTA)  
4. Lighting (LUMA)  
5. Noise/vibration control (APLO, MEDI)  
6. Neighbourhood synchronisation (NEMO)

This phase answers:  
**“What should the organism do?”**

---

## 3.4 Phase 4 — **Action** ⚙️  
The loop issues coordinated commands:

- HVAC soft‑starts  
- LUMA fades  
- APLO cycles stagger  
- MEDI volume adjusts  
- MOTA path lighting activates  
- SAC locks/unlocks  
- ENVO recalibrates  
- NEMO predictions update  

All actions must follow the **Soft‑Action Physics**:

- ramp, don’t snap  
- stagger, don’t stack  
- smooth, don’t spike  
- anticipate, don’t react  

This phase answers:  
**“How should the organism move?”**

---

# 4. Timing: The Tick  
The Runtime Loop runs at a fixed interval — the “tick.”  
The tick must be:

- short enough to feel responsive  
- long enough to avoid jitter  
- stable enough to maintain identity  

The tick is the **pulse** of the organism.

---

# 5. The Global State Object  
The loop maintains a minimal internal state:

- current environmental envelope  
- predicted envelope drift  
- subsystem readiness  
- dominance posture  
- residual tension (noise, vibration, pressure)  
- occupant posture  
- neighbourhood context  

This state is updated every tick and passed through all phases.

---

# 6. Why the Runtime Loop Works  
The loop works because it is:

- **simple** (four phases)  
- **predictable** (fixed tick)  
- **physiological** (organism model)  
- **coordinated** (dominance engine)  
- **soft** (behaviour physics)  
- **identity‑driven** (timing jitter, micro‑delays)  

It creates the illusion of a living presence without requiring cognition, emotion, or high‑level AI.

---

# 7. The Organism Effect  
When the loop runs continuously:

- the house feels calm  
- actions feel intentional  
- transitions feel natural  
- nothing clashes  
- nothing surprises  
- nothing snaps  

This is the **Edencore signature** — the behavioural identity that separates it from every other smart‑home system.

---

# 8. Conclusion  
The E‑CORE Runtime Loop is the nervous system of the Edencore organism.  
It senses, interprets, coordinates, and acts — continuously, softly, and predictably.  
It is the mechanism that turns eight subsystems into one coherent presence.

This loop is the heart of the architecture.
