# E‑CORE  
## Edencore Coordinated Organism Runtime Environment  
### (System Architecture Overview — Mode 2)

---

## 01 — Purpose of E‑CORE
E‑CORE defines the internal architecture, subsystem taxonomy, and behavioural coordination model that allows the Edencore home system to function as a coherent, organism‑like entity.  
It is the structural skeleton beneath all Edencore behaviour: physical, environmental, sensory, and narrative.

E‑CORE is not a protocol.  
It is not a smart‑home platform.  
It is the **organism model** that unifies all IoT subsystems into a single behavioural engine.

---

## 02 — Core Principles
E‑CORE is built on four foundational principles:

### **A. Organism Analogy**
The house behaves like a biological system:
- HVAC as lungs  
- Lighting as eyes  
- Security as skin/perimeter  
- Sensors as nerves  
- Appliances as muscles  
- Media as voice  
- Mobility systems as limbs  
- Neighbourhood mesh as external senses  

### **B. Coordinated Behaviour**
Subsystems do not act independently.  
E‑CORE synchronises them to avoid conflict, noise, vibration, or discomfort.

### **C. Human‑Centric Comfort**
Every action is grounded in physical reality:
- airflow  
- pressure  
- light levels  
- noise  
- vibration  
- timing  

### **D. Predictive Softness**
The system anticipates discomfort and smooths it before it happens.

## 03 — The Eight Subsystems of E‑CORE  
These are the canonical, pronounceable, vowel‑containing subsystem codes.

### **01 — HVAC**  
Heating, Ventilation & Air Conditioning  
Environmental stability, airflow, pressure, humidity, noise, vibration.

### **02 — LUMA**  
Lighting & Ambient Systems  
Illumination, mood, path guidance, visual comfort.

### **03 — SAC**  
Security & Access Control  
Perimeter awareness, entry/exit logic, presence detection.

### **04 — ENVO**  
Environmental Sensors  
Temperature, humidity, CO₂, vibration, sound, particulate, pressure.

### **05 — APLO**  
Appliances & Utilities  
Mechanical cycles, compressors, pumps, ignition events, load balancing.

### **06 — MEDI**  
Media & Communication Devices  
Audio, visual, notifications, intercom, household soundscape.

### **07 — MOTA**  
Mobility & Assistance  
Blinds, curtains, automated doors, stair lights, accessibility devices.

### **08 — NEMO**  
Neighbourhood Mesh  
External signals, weather shifts, local activity, shared timing patterns.

## 04 — E‑CORE Coordination Model
E‑CORE operates as a **runtime environment**, not a command system.  
It continuously evaluates:

- occupant state  
- environmental state  
- subsystem readiness  
- predicted discomfort  
- timing conflicts  
- noise/vibration risk  
- neighbourhood context  

Then it orchestrates the eight subsystems to behave as a single organism.

Examples:
- HVAC soft‑starts when APLO compressors are idle  
- LUMA adjusts brightness based on ENVO light readings  
- SAC entry events trigger HVAC pressure smoothing  
- MEDI volume adapts to ENVO sound levels  
- MOTA path lighting activates based on SAC movement  
- NEMO pressure shifts pre‑adjust HVAC airflow  

This is the “living house” effect.
